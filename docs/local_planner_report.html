阶段 0触发：什么时候需要一条新轨迹

① 收到新目标 → 进入 GEN_NEW_TRAJ（have_new_target_ = true）
② 走满前视阈值 → 相对轨迹起点实际推进 1.0 m（fsm.thresh_replan）即允许常规重规划；距起点不足 replan_thresh_ 时明确不重规划（避免抖动）
③ 安全循环（50 ms）沿轨迹采样发现碰撞 → 抢救式重规划，来不及则急停
④ 参考系跳变（mode 3）→ 参考 TF 平移 > 0.2 m 或偏航 > 5° 时以实测状态重规划本分支

补充：同一状态下的连续重试带退避 0.2→0.4→0.8→1.0 sP6； 另有"原地打转守卫"（位移 ≤0.15 m 且累计转角 ≥180° → 判失败并重取目标）P14。

阶段 1取局部目标：把全局轨迹变成一个"可执行的点 + 速度"

  • 在全局轨迹上定位机器人当前对应的时刻（投影），沿轨迹累计弧长到 fsm.planning_horizon = 5.0 m（A2 当前值），取该处位置为局部目标、该处速度为局部目标速度。
  • 目标落在障碍里 → 沿轨迹向前/向后各扩展搜索一个可站点替代；找不到则本轮放弃（NO_FREE_TARGET）。
  • 局部目标距最终终点 < 刹车距离 时，目标速度置零。
    braking_distance = max_vel² / (2·max_acc) = 1.0²/(2×1.5) = 0.33 m修正：不是 1.0 m
  • mode 3 下：终点 end_pt_ = reference_to_world × reference_end_pt_，位置/速度都要过一遍参考系变换。

阶段 2造草稿：先要一条"能连起来"的初始猜测

A 分支（新目标 / 强制多项式 / 首次）

  • 按梯形速度曲线估时长：T = (d − v²/a)/v + 2v/a（A2：v=1.0, a=1.5） ⇒ 5 m 约 5.67 s、2.5 m 约 3.17 s修正：不是固定 4.5 s
  • 解一条单段五次多项式，六个边界条件（起点 p/v/a、终点 p/v/a）。

B 分支（常规重规划）

  • 沿旧轨迹从当前时刻采到末尾；末端与新目标还差一截就补一段五次多项式接过去（保持速度/加速度连续）。
  • 失败降级链：续接 → 多项式 → 带随机中点的多项式。

阶段 3采样与高度：把连续曲线离散成点集

  • 按时间步长打点，要求相邻点距 ≤ ctrl_pt_dist×1.5 = 0.3 m、点数 ≥ 7，否则缩短步长重来。
  • 高度重写 applyLinearZReference()：按水平累计距离的比例，从起点高度线性插值到目标高度（首尾强制对齐）。目的：四足走平地时高度不该忽高忽低。

阶段 4B 样条参数化：连续 → 可优化

  • 用点集 + 四个边界导数解超定线性方程组，得到 K+2 个控制点。
  • 阶数 3、时间间隔 ts = ctrl_pt_dist / max_vel × 1.2 = 0.2/1.0×1.2 = 0.24 s（若 max_vel 改回 0.75 则为 0.32 s）。
  • 此后任意时刻的位置、速度、加速度都可求 ⇒ 后续所有检查与下发都基于这条曲线。

阶段 5避障准备：给每个撞墙控制点一个"往哪推"

  • 沿控制点连成的折线细密采样，只检查前 2/3 的控制点，找出所有连续碰撞段。
  • 每段跑一次 A\*（池子 160³，覆盖 ±4 m，以段中点为中心）得到绕行路线。
  • 求"控制点切线"与 A\* 路线的交点 ⇒ 每个撞墙控制点得到一组 基点（障碍表面）+ 方向（外法线）。
  • 本分支的健壮化：A\* 失败不再"与下一段合并"（越并越长），改为二分重试；最短段仍失败时用障碍法线兜底给出方向P15。

阶段 6L-BFGS 优化：最终形状

  • 优化变量：中间控制点的 x、y（z 梯度清零，不优化）。首尾各 order_=3 个控制点锁死 ⇒ 起点若在障碍里，优化器救不回来（这解释了历史上 START_IN_OBSTACLE 的顽固性）。
  • 三项代价：平滑（四阶差分近似 jerk）、避障（沿方向离开障碍表面的距离不足安全距离就罚）、可行性（速度/加速度超限就罚）。
  • 优化中途发现新碰撞 → 中断本轮、重算方向、从头再来（STOP_FOR_REBOUND）。
  • 求解后仍碰撞 → 避障权重加倍重启，最多 3 次；第 3 次仍失败才判本轮失败。

阶段 7可行性修正：几何不动，只拉长时间轴

  • 检查是否超速/超加速度；超限就按超限倍数把时间轴整体拉长 ⇒ 几何路径不变、速度成比例下降、加速度按平方下降。
  • 拉长后重新采样并做一次细化优化，用各向异性贴合把轨迹拉回原形状：纵向允许偏 25×、横向只允许 1×（横向更严格，保证不贴边）。
  • 修正后仍不可行 → 丢弃，本轮失败（DYNAMIC_INFEASIBLE / REFINE_UNSAFE）。

阶段 8复核与发布

  • 再按细步长采一遍，核对速度/加速度模长是否达标（同样只查前 2/3）。
  • 通过后把位置/速度/加速度三条曲线写入 local_data_，轨迹编号 +1。
  • 打包成 Bspline 消息（控制点 + 节点向量 + 阶数 + 起始时刻 + 编号）发布到 /planning/bspline，同时发一份 /local_path 供观察。

阶段 9控制层：每 10 ms 一条机体系速度

  • 用控制点 + 节点向量重建 B 样条并求导得速度曲线。
  • 参考时刻跟随实际进度：exec_time 被夹在「机器人实际投影进度 + time_lead 0.2 s」以内，不再开环推进P3。
  • 用前方 0.8 s（time_forward）处的点估算期望朝向；朝向误差 > 0.8 rad → 发冻结信号、只输出角速度（原地转向，上限 1.2 rad/s）；否则解除冻结、推进执行时间。
  • 期望世界系速度 = 轨迹速度 + 位置误差 × 0.8（kp_pos），限幅（0.75 / 0.35 m/s）后转到机体系发 /cmd_vel。
  • 轨迹走完且位置误差 < 0.15 m → 全零停车。
  • 三个保护：轨迹整体超时（dur + 3 s 丢弃并发 0）P2； 卡住刹停（"想动但实测不动"持续 1.0 s → 冻结 + 停）P5； 冻结期间超时判定顺延P19。

阶段 10反馈回环：让"时间"锚在实测上

  • /cmd_vel → 执行机构 → 位姿更新 → /lio/robo/odom 回到规划器，成为下一轮起点。
  • 轨迹时钟连续夹住：t_cur 不得超过「实际投影进度 + 0.3 s」P4（一处改动，5 个消费者同时生效）。
  • 冻结信号回传状态机 → 原地转向期间暂停轨迹时钟；结束/放弃时发一条"停在原地"轨迹让控制器立即刹停P1。
  • 无进展收尾：以墙钟计（提交后 ≥3 s 且几乎不动）判本段结束，避免"时钟被夹住 ⇒ 永不收尾"P16/P19。
  • 50 ms 安全循环：沿轨迹采样查碰撞，跳过"当前位置附近 0.25 s"（机器人自身常在自己膨胀层里）P17a； 发现碰撞 → 抢救式重规划，来不及（<1.0 s）→ 急停。

三个结构性薄弱环节 已知、有实测依据、后续工作接口

①碰撞检查只覆盖前 2/3

阶段 5（避障准备）、阶段 8（复核）、阶段 10（安全循环）三处都只查 2/3 的轨迹时长，控制器侧完全没有碰撞检查。 对 6 s 的局部轨迹，最后约 2 s（1~2 m）从未被校验 ⇒ 若该段穿障碍，仍会被发布并被跟踪。

②投影在"折返路径"上有二义

阶段 1 在整条全局轨迹上找"离机器人最近的点"。折返楼梯的两跑在 XY 上几乎重叠（只差约 2 m 高度）， 最近点可能被吸到另一跑 ⇒ 局部目标跑到目标的反方向 ⇒ 局部目标朝反方向、d_goal 单调增大。

实测：|局部目标 − 真目标| 平均 4.0 m、最大 8.5 m； 典型一帧 target=(7.70,3.93) vs goal=(3.58,5.48)，d_target 4.39 / d_goal 4.26，bearing 64°（有时 ±180°） 一次"带 z 门限 + 单调"的尝试曾把局部目标锁死在南边 1 m（d_target=1.05、traj_dur=1.68 s），已回退

③全局路径与局部地图不一致

全局规划器 robot_radius: 0.0（不膨胀），路径按"质点"搜索 ⇒ 可能穿过局部地图判定为障碍的结构。 局部规划器只能忠实跟随 ⇒ 初始路径穿墙 ⇒ 控制点成串落入膨胀层 ⇒ A\* 连串失败（二分到 0.1~0.4 m 仍失败）⇒ 法线硬推 ⇒ 优化失败 / 动态不可行 ⇒ 撞点在 0.5 s 内 ⇒ 急停。
