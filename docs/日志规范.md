# 日志规范

本文约定 SCAN-Planner 第一方代码的日志格式、级别与频率，供现场排查、录包分析和 CI 检查使用。

## 格式

一条日志一行，统一为：

```text
[模块] event=<事件> rid=<n> traj_id=<n> seg=<n> ok=<0|1> reason=<枚举> <key=value...>
```

- 模块固定为：`fsm`、`map`、`astar`、`opt`、`ctrl`、`sim`、`sys`。
- `rid` 是一次重规划的关联号，FSM、A*、优化器的日志应携带同一个 `rid`。
- 时间、距离、角度统一带单位：`s`、`m`、`deg`、`m/s`。
- 禁止在日志里使用 `\n`、`\t` 或 ANSI 颜色转义。

示例：

```text
[fsm] event=state from=GEN_NEW_TRAJ to=EXEC_TRAJ trigger=FSM
[fsm] event=goal_degraded rid=42 from=(10.00,2.00,0.50) to=(9.20,2.00,0.50) shift=0.80m
[fsm] event=memory_error rid=42 traj_id=17 reason=bad_alloc action=emergency_stop plan_ms=12.3
[astar] event=init_err rid=42 seg=1 adj_s=0.35m adj_e=0.00m
[astar] event=path_cycle rid=42 seg=1 path_len=1234 limit=2560000 node=(10,20,30)
[astar] event=path_too_long rid=42 seg=1 path_len=2560000 limit=2560000 node=(10,20,30)
[opt] event=replan rid=42 ok=0 reason=astar_no_path
[sim] event=collision kind=environment hits=12 pos=(1.00,2.00,0.30)
```

`path_cycle` / `path_too_long` 表示 A* 的 `cameFrom` 链异常，路径没有交给优化器；`memory_error` 表示重规划期间内存分配失败，FSM 会转急停而不是退出进程。两者都按 `WARN`/`ERROR` 级别、带 `rid`/`seg` 记录。

## 级别

| 级别 | 用途 | 频率约束 |
|---|---|---|
| `ERROR` | 状态机无法继续、需要人工处理 | 同一原因节流 ≥1s |
| `WARN` | 可自恢复但值得注意（绕行、降级、重试、TF 短暂缺失） | 同一原因节流 ≥1s |
| `INFO` | 启动摘要、状态迁移、目标接受/完成、使能/暂停、降级成功 | 每事件 1 条 |
| `DEBUG` | 每次重规划、A* 分段、优化迭代、可行性、时钟诊断 | 默认关闭 |

正常运行时 `ERROR` 应保持为 0；失败重试的每次尝试不再使用 `INFO`。

## 运行

```bash
# 默认：只显示主线事件
ros2 launch scan_planner run.launch.py log_level:=info

# 排查：显示重规划/优化/A* 明细
ros2 launch scan_planner run.launch.py log_level:=debug
```

A\* 的 4 条“平面占用图”和 13 行 ASCII 图默认关闭，需要单独打开：

```bash
ros2 param set /scan_planner_node fsm.diag_verbose true
```

`log_level:=debug` 只改变日志级别，不会自动打开这张图。

日志目录默认为 `~/.ros/log/`，可用 `ROS_LOG_DIR` 覆盖：

```bash
ROS_LOG_DIR=~/runs/debug ros2 launch scan_planner run.launch.py log_level:=debug
```

## 查询与导出

```bash
python3 tools/log_query.py summary run.log      # 总览/失败原因分布
python3 tools/log_query.py rid 42 run.log       # 按 rid 看完整链路
python3 tools/log_query.py last-failure run.log # 最后一次失败及其上下游
python3 tools/log_query.py errors run.log       # 只看 WARN/ERROR
python3 tools/log_query.py slow run.log         # 最慢的 A*/优化/重规划
python3 tools/log_query.py timeline run.log     # 状态迁移/卡住/后撤简表
python3 tools/log_query.py export run.log --out run.jsonl
```

诊断话题每秒发布一次（`std_msgs/String`，JSON）：

```bash
ros2 topic echo /local_planner/diagnostics
```

字段包括 `state/rid/traj_id/replans/replan_ok/replan_fail/degrade/backup/last_reason/plan_ms_*/failures`。

节点每 10 秒打印一条 `[sys] event=health`，退出时打印 `[sys] event=shutdown_summary`。

## 审计

```bash
python3 tools/log_audit.py            # 只报告
python3 tools/log_audit.py --strict   # 第一方裸输出/ANSI 存在时返回非 0
```

`tools/log_audit.py --strict` 已加入 CI，第一方代码（`src/planner`、`src/simulator` 的非 vendored 部分）不允许新增裸 `cout/cerr/printf` 或 ANSI 转义。
